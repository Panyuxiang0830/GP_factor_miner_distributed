## 0. 一句话概括

现有项目用 Python（pandas + 32 进程）分三层（表达式深度 1→2→3）进化出因子，用"PCA 签名 + 相似度档案"保证因子之间不重复。本项目把**因子批量评估引擎**用 C/C++ 重写，并做 **MPI（按日期切分）+ OpenMP + CUDA** 并行。重点有两个：

1. **分层生成**变成跨层的子表达式缓存，而且这个缓存只有在分布式内存里才放得下；
2. **PCA 签名**改成 GPU 上的批量排序和批量幂迭代，相似度矩阵用手写的分块 GEMM。

GP 的选择、交叉、变异逻辑仍然留在 Python 里，不重写。

## 1. 背景：什么是因子挖掘

- **面板数据**：每个原始字段（换手率、分钟级收益偏度……）都是一张 `交易日 × 股票` 的矩阵 $X \in \mathbb{R}^{T\times N}$。
- **因子**：由原始字段和算子组合成的表达式。例如 `ema(turnover_rate * minute_amount_skew, 5)`，计算结果也是一张 $T \times N$ 的矩阵。
- **好因子的标准**：在每个交易日，用因子值给股票排序，这个排序和未来收益的排序相关性越高越好。这个相关性叫 **RankIC**（Spearman 相关）：

$$
\mathrm{IC}_t = \mathrm{corr}\big(\mathrm{rank}(F_{t,\cdot}),\ \mathrm{rank}(Y_{t,\cdot})\big),\qquad
\overline{\mathrm{IC}} = \frac{1}{|T_{\text{valid}}|}\sum_t \mathrm{IC}_t
$$

- **遗传规划（GP）**：把表达式看成一棵树，用"选择 + 交叉 + 变异"在巨大的表达式空间里搜索 $|\overline{\mathrm{IC}}|$ 高且稳定的因子。
- **为什么计算量大**：每评估一个表达式，都要在整张面板上执行若干个算子，再对每个交易日做一次全市场排序。整个搜索要评估几十万个表达式。

### 2.2 表达式表示

- 用嵌套列表表示，例如 `['ema', ['*', ['+', 'a', 'b'], ['+', 'c', 'd']], 5]`。最后的整数是窗口长度。
- **规范化**（`normalize_expression`）：
  - `+` 和 `*` 的两个操作数按字典序排序，所以 `a+b` 和 `b+a` 视为同一个表达式；
  - `rank(rank(x))` 化简为 `rank(x)`；
  - `x−x` 和 `x/x` 判为退化表达式，直接丢弃。
- 规范化后的 JSON 字符串作为表达式的唯一键（`expression_key`），用来去重和查缓存。
- **约束**：每层的深度不超过当前层的上限（1、2 或 3）；节点数不超过 11；窗口长度从 {1, 5, 10, 15, 20, 30, 60} 中取。

### 2.3 算子（20 个，pandas 实现）

| 类别 | 算子 | 语义要点 |
|---|---|---|
| 逐元素 | `+ - * /`、`log`、`abs` | `/` 在分母绝对值小于 1e-12 时输出 NaN；`log` 对非正数输出 NaN；inf 一律转成 NaN |
| 横截面 | `rank`（当日百分位排名，并列取平均）、`zscore`（当日标准化） | 每一行（每个交易日）单独计算 |
| 时间序列滚动 | `mean sum median`（`min_periods=1`）；`std max min`（`min_periods=min(3,w)`）；`ema`（`span=w`，`adjust=False`）；`lag`、`delta`、`pct_change` | 每一列（每只股票）单独计算 |
| 双变量滚动 | `correlation(a,b,w)`、`beta(a,b,w)` | 滚动协方差除以滚动方差，`min_periods=min(3,w)` |

### 2.4 适应度 [现有]

对每个表达式：

1. 先求值得到因子面板 $F$，再计算每日 RankIC 序列 $\{\mathrm{IC}_t\}$；
2. **过滤**：有效 IC 的日期占比必须 ≥ 0.80，因子缺失率必须 ≤ 0.20，否则淘汰；
3. 把 IC 序列按时间平均切成 4 段，得到 4 个段均值 $m_1,\dots,m_4$；
4. 计算适应度：

$$
\text{fitness} = |\overline{\mathrm{IC}}| - 0.5\cdot \mathrm{std}(m_1..m_4) - 0.0005\cdot\max(\text{nodes}-3,0)
$$

5. 如果 4 段里和总体同号的比例小于 0.75，适应度再乘以 0.25。

所以这个适应度同时奖励**强度**（IC 大）、**稳定性**（各段 IC 接近）和**简洁**（节点少）。

### 2.5 分层进化（亮点一）[现有]

```
深度 1 层 ──► 基因池 G1（≤2000）
                │  70% 概率从 G1 抽子树作为孩子
深度 2 层 ──► 基因池 G2（≤2000）
                │  从 G1、G2 抽子树
深度 3 层 ──► 基因池 G3 ──► 2022 年样本外终筛
```

每一层的流程：

1. **热启动**：生成 3 × 10000 = 30000 个提案（`balanced_stage_proposals`），让各种根算子的数量均衡。从第 2 层起，每个子节点有 70% 的概率直接用下层基因池里的一个基因，30% 的概率用原始字段。
2. **父代池**：按适应度从高到低挑出 2000 个父代，并限制每个原始字段的出现占比（依次放宽为 15%、20%、30%），防止父代全部集中在少数几个字段上。
3. **选择**：50% 的概率用锦标赛选择（每次抽 3 个）；50% 的概率用 **ε-lexicase**，即以 4 个时间段的 IC 作为 4 个"考题"，按随机顺序逐题淘汰，奖励在各个时间段都表现好的个体。
4. **交叉和变异**：
   - 同层交叉的概率是 0.7，只在树的同一层之间交换子树，交换后不能超过本层深度上限；
   - 变异包括换字段（0.15）、换算子（0.10）、换窗口（0.10）和子树变异（0.10）；
   - 每对父母和它们的孩子组成一个家庭，只保留家庭里适应度最高的 2 个；另外每代引入 10% 的随机移民。
5. 每层进化 10 代，每个新个体都要经过 PCA-QD 档案的准入判断（见 2.6）。
6. **晋升**：本层被档案接纳的记录按适应度排序，取前 2000 个作为本层的基因池。

**直觉**：先在浅层找到好的"积木"，再拼装成深层表达式。这样搜索空间是逐层受控地增长，而不是一开始就面对全部深度为 3 的树。

### 2.6 PCA-QD 签名与档案（亮点二）[现有]

**目的**：GP 很容易产生大量几乎相同的因子，比如 `std(x,10)` 和 `std(x,15)`。QD（Quality-Diversity）档案的作用是保证"相似的因子只留下最好的一个"。直接比较两个 $T \times N$ 的面板太贵，所以先把每个因子压缩成一个**签名**向量。

**签名的计算**（`factor_signature`）：

1. 每隔 5 天抽一行，得到 $T_s = \lceil T/5 \rceil \approx 292$ 行；
2. 每行在股票之间算百分位排名，NaN 和 inf 填成 0.5，然后每行减去自己的均值，得到 $R \in \mathbb{R}^{T_s\times N}$；
3. 用**幂迭代**求 $R$ 的第一右奇异向量。$v_0$ 是固定种子下的随机单位向量，迭代 4 次：

$$
u \leftarrow \frac{R v}{\|R v\|},\qquad v \leftarrow \frac{R^\top u}{\|R^\top u\|}
$$

4. 签名 $s = R v / \|R v\|$，长度为 $T_s$，含义是每个抽样日在第一主成分方向上的得分。为了消除正负号的歧义，规定绝对值最大的那个分量必须为正。

**相似度与准入**（`PCAQDArchive.consider_batch`）：

- 签名先中心化再归一化，两个签名的相似度就是 $|\langle \hat s_i, \hat s_j\rangle|$，也就是 |Pearson 相关|。
- 候选按每块 128 个处理，一次计算两个矩阵：候选对档案的 $|\hat S_c \hat S_a^\top|$，和候选彼此之间的 $|\hat S_c \hat S_c^\top|$。**[现有] 只有这一步在 CUDA（torch）上运行**，并且关闭了 TF32，用严格的 FP32 计算。
- 准入规则（按顺序逐个判断）：
  - 和档案里所有记录的相似度都低于 0.90：直接加入；
  - 否则和最相似的那个比较，RankIC 至少高出 0.002 才替换它，不然拒绝。
- 数值安全：先用 float32 粗算，对接近阈值的情况和"最大值并列"的情况，再用 float64 的误差界复核，保证判断结果和旧版纯 float64 实现完全一致。

### 2.7 终筛 [现有]

三层全部结束后才在 2022 年数据上终筛：

1. 要求 $|\mathrm{IC}_{2022}| \ge 0.07$，并且方向和进化期一致；
2. 按质量从高到低贪心选取：把每个因子"每隔 5 天抽样后的全截面排名"展平成一个向量（长度约 $T_s \times N$），新因子和已选的每个因子的 |相关| 都必须小于 0.75 才保留。

终筛不影响进化过程。

### 2.9 现有的并行方式与瓶颈

| 环节 | 现在怎么做 | 问题 |
|---|---|---|
| 表达式求值 | `fork` 出 32 个进程，每个进程负责一个表达式，用 pandas 递归求值 | pandas 有大量临时 DataFrame 和对齐开销；滚动窗口要重复计算；进程之间不共享中间结果 |
| 子表达式复用 | `ExpressionCache()` 在**每个任务里新建一个**，只缓存最终的 `Candidate` 结果 | **深度 3 表达式里来自 G1、G2 的子树，每次都从原始字段重新算一遍**，分层带来的复用完全没有利用 |
| RankIC | 每个表达式对 $T$ 天各做一次 pandas 排序 | 每天对 5000 个数排序，一共要做 $T \times$ 表达式数次 |
| PCA 签名 | numpy，在 worker 里单线程计算 | 排序加 4 次幂迭代，每次都要读一遍 $R$ |
| 相似度 | torch CUDA | 只有这一步用了 GPU，而且矩阵很小（128 × 档案大小 × 292） |

## 4. 改进一：算子与求值引擎 [计划]

### 4.1 数据布局

- 面板用 `float32 data[T][N]` 存储，**按日期为主序（行优先）**，另外配一张 `uint8 mask[T][N]` 标记可交易的样本，NaN 沿用 IEEE NaN。
- 这样选择的原因：
  - 横截面操作（排序、IC、签名）都是按"一行 = 一天"连续访问；
  - 按日期切分时，每个 rank 拿到的是一段连续的行，halo 也正好是连续的若干行，可以直接用一次 `MPI_Sendrecv` 发出去；
  - 时间序列算子按列访问，跨步较大，但同一天的 N 只股票可以由 OpenMP 线程或 CUDA 线程**并行处理**，每个线程负责一只股票，相邻线程访问相邻地址，访存是合并（coalesced）的。

### 4.2 滚动算子：从 $O(Tw)$ 降到 $O(T)$

pandas 的部分滚动统计每个窗口都要重新计算，C++ 版统一改成滑动窗口的增量更新：

| 算子 | 算法 | 注意 |
|---|---|---|
| `sum`、`mean` | 维护窗口内的累加和与有效样本数 | NaN 不计入有效样本，`min_periods` 必须和 pandas 一致 |
| `std` | 维护 $\sum x$ 和 $\sum x^2$，**用 double 累加** | float32 下 $E[x^2]-E[x]^2$ 会发生灾难性抵消；pandas 的 `std` 用的是 ddof=1 |
| `max`、`min` | 单调双端队列，每个元素均摊 $O(1)$ | 要处理 NaN 跳过的情况 |
| `correlation`、`beta` | 维护 $\sum a$、$\sum b$、$\sum ab$、$\sum a^2$、$\sum b^2$ 和成对的有效样本数 | 这是使用最多的两个滚动算子，收益最大 |
| `ema` | 递推 $y_t = (1-\alpha) y_{t-1} + \alpha x_t$，其中 $\alpha = 2/(w+1)$ | 要和 pandas `adjust=False` 的 NaN 处理方式对齐；分布式时用前缀扫描（见 6.3） |
| `lag` | 整行平移 | — |

逐元素算子（`+ - * / log abs`）做**算子融合**：一条只包含逐元素算子的子链只需要读一次输入、写一次输出，不再为每个算子生成一张临时面板。

### 4.3 子表达式 DAG 与跨层缓存（把亮点一变成性能）

- 一批表达式先全部规范化，然后**合并成一张 DAG**：键相同的子树只算一次（公共子表达式消除）。
- 基因池 G1、G2 的面板结果**常驻缓存**。深度 3 的表达式里，凡是来自基因池的子树都直接读取缓存，剩下的往往只需要再算 **1–2 个算子**。
- 内存估算：一张面板约为 $1460 \times 5000 \times 4\,\text{B} \approx 29$ MB，所以 2000 个基因约 58 GB，G1 加 G2 约 117 GB。
  - 单张 3090 只有 24 GB 显存，放不下；
  - 按日期切到 $p$ 个 rank 上之后，每个 rank 只需要 $117/p$ GB。例如 8 张卡时每张约 15 GB，就能放进显存。
  - 这说明**分布式在这里不只是为了提速，也是为了让缓存放得下**。
- 显存仍然不够时可以退而求其次：缓存放在主机内存里（gpushare 有 2 TB），GPU 上用 LRU 管理热点子树；或者只缓存最常被引用的子树。
- 实验指标：缓存命中率；开缓存和关缓存时每代的耗时；DAG 合并后实际执行的节点数和原始节点数之比。

### 4.4 语义对齐风险

pandas 的语义细节是最容易出现"算得很快但结果不对"的地方：

- `min_periods` 的规则；
- NaN 在窗口里怎么计数；
- 排名遇到并列时取平均；
- `ewm(adjust=False)` 遇到 NaN 的行为；
- 除法的阈值 1e-12；
- inf 一律转成 NaN。

**每实现一个算子，就在小面板上和 pandas 逐元素比对一次**（见第 8 节）。

## 5. 改进二：用 CUDA 处理排序与 PCA 签名 [计划]

GPU 上的流水线：对一批 $B$ 个因子，在 GPU 上一口气完成下面的步骤，中间结果不回到 CPU。

```
因子面板 F_b (T×N, 已在显存)
  ├─► 逐日横截面排名 ─► 与标签排名求每日 IC ─► 段均值 / 适应度   (RankIC)
  └─► 每 5 天抽样 ─► 逐行排名、NaN 填 0.5、行去均值 ─► R_b (T_s×N)
          └─► 批量幂迭代 4 次 ─► 签名 s_b (T_s)
                 └─► 签名归一化 ─► 分块 GEMM: |Ŝ_c Ŝ_aᵀ|, |Ŝ_c Ŝ_cᵀ|
                         └─► 只把接近阈值的候选和相似度回传 CPU ─► 顺序准入
```

### 5.1 Kernel 1：分段排名（RankIC 和签名共用）

- 每个线程块负责一个 (因子, 日期) 对，即一行 $N \approx 5000$ 个元素。值加下标一共约 40 KB，**整行可以放进 shared memory**（默认上限 48 KB）。
- 块内排序可以用 bitonic 排序，或者 CUB 的 `BlockRadixSort`。排好后，对相等值组成的连续段做一次扫描，得到"平均排名"，再除以有效样本数得到百分位。
- RankIC 的标签排名每天只需要算一次，算好后常驻显存。每日 IC 就是两个排名向量的 Pearson 相关，在块内做归约即可得到。

### 5.2 Kernel 2：批量幂迭代

- 每次迭代计算 $u = R v$（$T_s$ 个点积，每个长度为 $N$）和 $v = R^\top u$（$N$ 个点积，每个长度为 $T_s$）。
- $B$ 个因子一起算，就是 batched GEMV。它是**访存受限**的：4 次迭代共 8 遍，每遍都要完整读一次 $R$。$R$ 本身只有 $292 \times 5000 \times 4\,\text{B} \approx 5.8$ MB。
- 优化方向：
  - $R$ 用 float32 常驻显存；
  - 把"求 $Rv$ 后归一化"和"求 $R^\top u$"融合进同一个 kernel，减少 kernel 启动次数和全局内存读写；
  - 用 roofline 模型分析结果：理论带宽约 936 GB/s，对比实测达到的带宽。
- 确定性：初始随机向量 $v_0$ 必须和 Python 用同一个种子生成。最简单的做法是在 Python 端生成后导出给 C++。

### 5.3 Kernel 3：签名相似度（分块 GEMM）

- 计算 $|\hat S_c \hat S_a^\top|$：大小为 $B \times A$，内积维度 $d = T_s \approx 292$。
- 手写**分块共享内存矩阵乘**（对应 Lecture 9 讲的分块和 Lecture 10 讲的 shared memory），再和 cuBLAS 对比，并关闭 TF32，和现有代码保持一致。
- 输出时直接在 kernel 里比较阈值，只回传每个候选的最大相似度、对应的档案位置，以及所有接近阈值的候选对。这样**不需要把整个 $B \times A$ 矩阵拷回 CPU**。

### 5.4 [可选] 终筛的全向量相关

终筛要两两比较 1481 个因子，每个向量长约 $292 \times 5000 \approx 1.46$M，本质上是计算一个 Gram 矩阵 $V V^\top$。这是典型的**计算受限**的 GEMM，非常适合 GPU，也可以用 MPI 按向量维度切分后做 Allreduce。如果时间允许，可以作为第二个 CUDA 案例：一个访存受限，一个计算受限，正好形成对比。

### 5.5 数值精度

- GPU 的归约顺序和 CPU 不同，再加上浮点加法不满足结合律，签名会有 ULP 级别的差异。
- 沿用现有代码的思路：**只有落在阈值 ± 误差界范围内的候选对，才用 double 复核**。验证目标是准入决定和 Python 版完全一致。

## 6. 分布式设计：MPI + OpenMP + CUDA [计划]

### 6.1 切分方式：按日期切分

$p$ 个 rank 各自持有连续的 $T/p$ 天，每个 rank 负责全部 $N$ 只股票；每个 rank 绑定一个 GPU（CUDA 版），或者一个 NUMA 域加若干 OpenMP 线程（CPU 版）。

| 计算 | 是否需要通信 | 通信方式 |
|---|---|---|
| 逐元素算子 | 不需要 | — |
| 滚动窗口算子 | 需要前 $h$ 天的数据 | 和左邻居做一次 **halo 交换**（`MPI_Sendrecv`，可以改成 `Isend/Irecv` 并和内部计算重叠） |
| `ema` | 依赖全部历史 | **仿射变换 + `MPI_Exscan`**（见 6.3） |
| 每日排名和每日 IC | 不需要（每天只用当天的数据） | — |
| IC 均值和 4 段均值 | 需要 | 每个 rank 先按全局日期下标把 IC 分到 4 段，算出局部的 (和, 有效天数)，再做一次 `MPI_Allreduce`，打包后共 $B \times 4 \times 2$ 个数 |
| 签名所需的抽样行 | 不需要 | 按**全局**下标 `t % 5 == 0` 判断，不能用本地下标，否则抽样的日期会错位 |
| 幂迭代中的 $u = Rv$ | 不需要（每个 rank 持有 $u$ 的一部分） | $\|u\|^2$ 需要做一次 Allreduce |
| 幂迭代中的 $v = R^\top u$ | 需要 | **把长度为 $N$ 的向量做 Allreduce**；$B$ 个因子合并成一次，共 $B \times N$ 个数，以减少通信启动开销 $\alpha$ |
| 签名汇总 | 需要 | `MPI_Gatherv` 到 rank 0（数据量只有 $B \times 292$） |
| 相似度和准入 | rank 0 | 相似度在 rank 0 的 GPU 上算；准入是顺序决策，**属于串行部分** |

### 6.2 halo 长度要从表达式树推导

一个节点需要的回看天数，等于它自己的窗口减 1，再加上子节点里最大的回看天数：

$$
h(\text{node}) = (w_{\text{node}} - 1) + \max_{\text{child}} h(\text{child}),\qquad h(\text{leaf}) = 0
$$

例如 `correlation(std(x,10), y, 20)` 需要回看 $19 + 9 = 28$ 天。

两种做法：

- **一次拿够**：按整棵树的最大 $h$ 只交换一次。通信次数少，但会有冗余计算。
- **逐节点交换**：每个滚动节点各交换一次。数据量少，但通信次数多。

这本身就是一个可以写进报告的设计取舍，可以都实现出来做对比。

**扩展性的极限**：每个 rank 的冗余工作量大约是 $h_{\max} / (T/p)$。$h_{\max}$ 最大可以接近 $3 \times 59 = 177$ 天，而 $T/p$ 随 $p$ 增大而变小，所以 $p$ 很大时 halo 开销会占主导。这是**强扩展曲线必然弯下去**的一个可解释原因，可以用 Karp–Flatt 指标来佐证。

### 6.3 `ema` 的并行前缀扫描

$y_t = a\,y_{t-1} + b_t$，其中 $a = 1-\alpha$，$b_t = \alpha x_t$。

- 每个 rank 负责的那一段，合起来等价于一个仿射变换 $y_{\text{end}} = A\,y_{\text{start}} + B$。
- 两个仿射变换的复合满足结合律：$(A_2, B_2) \circ (A_1, B_1) = (A_2 A_1,\ A_2 B_1 + B_2)$。

做法：

1. 每个 rank 先在本地算出自己那一段的 $(A, B)$。$N$ 只股票各有一对 $(A, B)$，NaN 的规则另外处理。
2. 用自定义的 `MPI_Op` 做 `MPI_Exscan`，得到"前面所有段合起来的变换"，也就是本段起点的初始值。
3. 各 rank 再在本地把自己那一段重新递推一遍。

### 6.4 OpenMP 层

- 线程在**股票维度**上并行：每个线程处理同一天的一批股票，用于时间序列算子；或者在**同一 rank 内的多个日期**上并行，用于横截面排序。
- 在 gpushare 上，cgroup 只分配了 **42 个核**的配额，而 `nproc` 显示 128，所以必须显式设置 `OMP_NUM_THREADS`；还要配合 `OMP_PLACES=cores` 和 `OMP_PROC_BIND=close`，并用并行的首次写入（first-touch）初始化数据，以照顾两个 NUMA 节点。
- 混合模式用 `MPI_Init_thread(MPI_THREAD_FUNNELED)`，只由主线程调用 MPI。

### 6.5 和 Python GP 的衔接

- 引擎编译成一个共享库：可以用 pybind11 暴露 `evaluate_batch(expressions) -> (IC 统计, 签名, 准入所需的相似度)`；也可以先用"写批次文件 → 调用 C++ 程序 → 读结果文件"的方式。
- 课程实验以 **C++ 驱动程序加固定的批次**为主，这样可以复现，也方便计时。批次直接取自 G1、G2、G3 和这 1481 个因子。完整跑一遍 GP 只作为最后的演示。

## 7. 实验设计

| 实验 | 对比内容 | 机器 |
|---|---|---|
| 基线 | Python 原版（32 进程）↔ 串行 C++ ↔ C++ + OpenMP，使用同一批表达式 | gpushare |
| 单卡 CUDA | 每个阶段 CPU 和 GPU 的耗时；3 个 kernel 实际达到的带宽或 FLOPS 与 roofline 的对比 | 3090 / Vanda |
| 强扩展 | 固定一批表达式，$p = 1, 2, 4, 8, \dots$；画出 S、E 和 Karp–Flatt 指标 | Atlas（CPU）/ Vanda（GPU） |
| 弱扩展 | 每个 rank 负责的天数不变（或每个 rank 的批次大小不变），$p$ 增大 | 同上 |
| 进程与线程配比 | 总核数固定，改变每个节点的 MPI 进程数和每个进程的线程数，例如 1×72、2×36、4×18 | Atlas |
| 时间拆分 | 计算 / halo / Allreduce / Gatherv / rank 0 串行准入，分别占多少 | 全部 |
| 缓存消融 | 关闭缓存 ↔ 只做 DAG 合并 ↔ DAG 合并加跨层缓存；记录命中率和每代耗时 | gpushare / Vanda |
| halo 策略 | 一次拿够 ↔ 逐节点交换 | Atlas |

**计时规则**：`MPI_Barrier` 之后用 `MPI_Wtime` 计时，各 rank 的耗时取 `MPI_MAX`；先预热；每个点重复 3 次以上，报告中位数。数据读取 I/O 单独计时，不计入核心计算时间。

## 8. 验证方案

1. **逐算子**：在随机小面板（含 NaN 和并列值）和真实数据切片上，把 C++/CUDA 的结果和 pandas 逐元素比对，要求最大相对误差 < 1e-5（float32）。
2. **逐因子**：抽取 1481 个因子里的一部分，比对每日 IC 序列；IC 均值的误差要求 < 1e-6。
3. **签名**：要求 C++ 签名和 Python 签名的 |余弦相似度| > 0.9999，并且正负号约定一致。
4. **QD 准入决定**：给定相同的批次和档案，两边的"加入 / 替换 / 拒绝"决定必须**完全一致**。
5. **分布式一致性**：$p = 1$ 和 $p > 1$ 时 IC 的差异必须在浮点误差以内，这一项专门用来检查 halo 和 `Exscan` 有没有写错。
6. **复现**：1481 个因子在 2022 年的 IC 和原有输出逐个对照，作为报告里"真实数据结论"的依据。

## 10. 报告里的重点（亮点清单）

1. **分层生成 → 跨层子表达式缓存**：把算法特性转化为性能，并且"必须分布式才放得下"。
2. **PCA 签名的 GPU 化**：分段排名、批量幂迭代、分块 GEMM。三个 kernel 分别对应 shared memory、访存受限和计算受限三类问题，配合 roofline 分析。
3. **分布式幂迭代**：和课上的 CG 例子是同一种模式（每次迭代做一次 Allreduce），并通过批量合并降低通信启动开销 $\alpha$。
4. **"天生串行"算子的并行化**：`ema` 用仿射扫描加 `MPI_Exscan` 实现。
5. **halo 长度由表达式树推导**，可以定量解释强扩展为什么会出现拐点。
6. **数值严谨**：float32 误差界加 double 复核，保证 QD 准入决定和原版完全一致。
7. **真实数据**：A 股 127 个字段、1481 个样本外因子的复现，以及在同样时间内能多搜索多少。
