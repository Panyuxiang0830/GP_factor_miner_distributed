## 1. 背景：为什么需要签名

GP（遗传规划）很容易产生大量几乎相同的因子，比如 `std(x, 10)` 和 `std(x, 15)`。项目用 **PCA-QD 档案**（Quality-Diversity）保证"相似的因子只留下最好的一个"。

直接比较两个 1461 × 5876 的因子面板太贵，所以先把每个因子压缩成一个短向量，叫**签名**，再比较签名。

每一代大约有 1 万个新因子要做这件事，热启动时约 3 万个。

## 2. 签名怎么算（现有的 Python 版）

代码：`python/src/gp_factor_miner/pca_qd.py` 的 `factor_signature`。

### 第 1 步：构造矩阵 R（每个因子一个）

1. 1461 个交易日里每 5 天取 1 天（全局下标 `t % 5 == 0`），得到 m = ⌈1461/5⌉ = **293 天**。
2. 每一天，把这个因子在 5876 只股票上的值排成百分位（0~1，并列取平均名次），NaN 填 0.5。
3. 每一行减去这一行的均值。

```
             股票1   股票2   ...  股票5876
第0天   [  0.31  -0.12  ...   0.05 ]
第5天   [  0.28  -0.20  ...   0.00 ]
 ...
第1460天[ -0.07   0.15  ...   0.22 ]
```

| 量 | 数值 |
|---|---|
| R 的大小 | m × n = **293 × 5876**（很"扁"：天数远少于股票数） |
| 一个 R | float32 约 6.9 MB；double 约 13.8 MB |
| 一代 1 万个因子的 R | float32 约 69 GB |

### 第 2 步：幂迭代求第一奇异向量

```
v = 固定种子的随机单位向量（长度 n）
重复 4 次:
    u = R v  / ‖R v‖      ← 长度 m = 293
    v = Rᵀ u / ‖Rᵀ u‖     ← 长度 n = 5876
签名 s = R v / ‖R v‖      ← 长度 293
让 s 中绝对值最大的元素为正（消除正负号歧义）
```

每一轮先乘 R 再乘 Rᵀ，等价于对 RᵀR 做一次幂迭代，所以 4 轮后 s 近似等于 R 的**第一个左奇异向量**。签名的含义是：每个抽样日的截面，和这个因子"最主要的截面模式"有多一致。

### 第 3 步：相似度与准入

代码：`PCAQDArchive.consider_batch`。

- 相似度：两个签名先中心化、归一化，相似度 = |内积|，也就是 |Pearson 相关|。
- 候选按每块 128 个处理，一次算出两个矩阵：候选对档案的 |Ŝ_c Ŝ_aᵀ|，和候选之间的 |Ŝ_c Ŝ_cᵀ|。
- 准入规则（**按顺序**逐个判断，前面的决定对后面的候选可见）：
  - 和档案里所有记录的相似度都低于 **0.90**：直接加入；
  - 否则和最相似的那个比较，|RankIC| 至少高出 **0.002** 才替换它，不然拒绝。
- 数值安全：先用 float32 粗算；对接近阈值或"最大值并列"的情况，用 float64 的误差界复核，保证决定和纯 float64 版本完全一致。

### C++ 版已经做了什么

E9–E11（串行签名）已经完成：`include/gpe/signature.hpp`、`src/core/signature.cpp`。

- `signature_rows`（第 1 步）：参数 `t0` 是本块第一天的全局下标，所以按日期切块后，每个 rank 只取自己那几天。
- `power_iteration`（第 2 步）：跨日期求和只有 ‖Rv‖² 和 Rᵀu 两处，都经过一个 `sum` 钩子：串行时为空，MPI 版换成 `MPI_Allreduce`。
- `finish_signature`：归一化、固定正负号、转成 float32。
- 初始向量由 Python 生成后写进文件（`pca_init.f8`），保证和 Python 一致。
- 验证：
  - 给定相同输入时，88/88 个用例和 Python 的 float32 签名逐位相同；
  - 用 C++ 自己算的因子值，完整数据上 88/88 通过，1 − 相似度最大 6.9e-6。

**还没做**：MPI 签名、准入（E12–E14）、CUDA、Lanczos。

## 3. 要解决的问题

### 问题 1：4 次幂迭代够不够？（老师的建议）

老师原话：*"If you have time, it would be interesting to compare power iteration against another iterative eigenvalue algorithm."*

- 幂迭代收敛速度取决于前两个奇异值之比。设 λᵢ = σᵢ²，迭代 k 次后，第二方向的残留比例大约是 (λ₂/λ₁)^k。
- 例子：λ₂/λ₁ = 0.9 时，0.9⁴ ≈ 0.66，**4 次后几乎没收敛**；要降到 1% 需要约 44 次。
- 如果很多因子的前两个奇异值很接近，签名就部分取决于随机初始向量，准入决定也可能随之改变。
- 对比算法建议用 **Lanczos 方法**（第 4 节）。

### 问题 2：怎么分布式地算签名和准入

- 第 ① 部分的引擎按**日期**切块：每个 rank 拥有连续的一段日期、全部股票。因子值算出来时，就是按日期分散在各个 rank 上的。
- 签名的计算需要跨日期求和；准入需要和整个档案比较，而且是**顺序**决定的（Amdahl 定律里的串行部分）。
- 评分要求 MPI 至少扩展到 **256 核**，并且做强扩展和弱扩展。

### 问题 3：GPU 版

- 评分要求 MPI+X；X = OpenMP 时，**还要在至少一块 GPU 上测试**。
- PCA 这部分天然适合 GPU：批量排序、批量矩阵向量乘、签名相似度矩阵乘。

### 一个要提前想到的风险

单个因子的计算量很小：4 次迭代约 9 × 293 × 5876 ≈ 1550 万次乘加；一代 1 万个因子约 1.5 × 10¹¹ 次，单个节点几秒就能算完。到 256 核时，**很可能是通信和串行准入占主导**。这本身就是值得报告的结论，但实验设计要考虑：
- 用热启动批量（3 万个）、多代合并，或者合成数据，增大问题规模；
- 把排名（每个因子 293 次长度 5876 的排序）和相似度计算也算进去，它们的计算量比幂迭代大。

## 4. Lanczos 方法（和幂迭代对比）

### 4.1 核心思想

幂迭代每一步算出 v, Av, A²v, …（A = RᵀR），但**只用最后一个**。

这些向量的任意线性组合 c₀v + c₁Av + … + c_kA^k v = p(A)v（p 是 k 次多项式）也能当作答案，而且**不需要多做矩阵乘法**。

- 幂迭代固定用 p(x) = x^k；
- Lanczos 在所有 k 次多项式里挑最好的：在这些向量张成的子空间（Krylov 子空间）里，把 A 投影成 k×k 的小矩阵，再精确求解（Rayleigh–Ritz）。

为什么会好很多：要让 p(A)v 只剩第一方向，需要 p 在 λ₁ 处大、在其他特征值处小。设 λ₁ = 1，其他特征值在 [0, 0.9] 内，把 p 缩放到 p(1) = 1，比较 p 在 [0, 0.9] 上的最大值（即"杂质残留"）：

| 次数 k | 幂迭代 x^k | 最优多项式（Chebyshev） |
|---|---|---|
| 4 | 0.66 | 0.145 |
| 8 | 0.43 | 0.011 |
| 降到 1% 需要几步 | ≈ 44 | ≈ 7 |

### 4.2 步骤（Golub–Kahan–Lanczos 双对角化，适用于长方形 R）

```
v₁ = 随机单位向量
p = R v₁;  α₁ = ‖p‖;  u₁ = p / α₁
for j = 1 … k-1:
    w = Rᵀ uⱼ − αⱼ vⱼ;   对 v₁…vⱼ 重正交化;   βⱼ = ‖w‖;   vⱼ₊₁ = w / βⱼ
    p = R vⱼ₊₁ − βⱼ uⱼ;  对 u₁…uⱼ 重正交化;   αⱼ₊₁ = ‖p‖;  uⱼ₊₁ = p / αⱼ₊₁
B = 上双对角矩阵（对角线 α₁…α_k，上对角线 β₁…β_{k−1}）
对 B 做 SVD，取最大奇异值对应的左奇异向量 y
签名 ≈ [u₁ … u_k] y，归一化，固定正负号
```

- B 的奇异值近似 σ₁、σ₂……，可以顺带估计间隙，判断签名是否可靠；也可以按残差自动停止，不固定步数。
- 浮点误差会让向量失去正交性。k 很小，直接做完全重正交化。
- **讲义第 16 页要求项目里不要用 BLAS / LAPACK**（包括 cuBLAS、cuSOLVER）。B 只有 k×k（k ≤ 20），它的 SVD 要自己写，比如对 BBᵀ（对称三对角）做 Jacobi 迭代。numpy 的精确 SVD **只能用在 Python 验证脚本里当参照**。

### 4.3 复杂度（m = 293，n = 5876，k 步）

| | 幂迭代 | Lanczos |
|---|---|---|
| 每步的矩阵乘法 | Rv + Rᵀu，2mn 次乘加 | 一样 |
| 额外计算 | 无 | 重正交化，总共约 k²(m+n)；k×k 的 SVD |
| 内存 | 2 个向量 | k 个 u + k 个 v |
| 每步的 MPI 通信（按日期切块时） | ‖Rv‖² 一个标量 + Rᵀu 长度 n 的向量 | 一样，再加 u 方向重正交化的 j 个点积（可以合并成一次 Allreduce） |

每步的代价几乎一样，但 Lanczos 每步的进展大得多。达到同样精度时，它需要的步数和 Allreduce 次数都更少。

## 5. 可能的分布式方案

### 5.1 签名：两种切分方式，需要实测比较

**方案 A：按日期（和引擎一致，已有 `sum` 钩子）**
- 每个 rank 只有自己那几天的抽样行（m/P 行 × n 列）。
- 每次迭代：u 的局部部分本地算；‖Rv‖² 和 Rᵀu 需要 Allreduce。
- 把 B 个因子打包成一次 Allreduce：每次迭代传 B × n 个 double。例如 B = 1000 时约 47 MB。
- P 增大时，计算量按 1/P 减少，**但 Allreduce 的数据量不变**，所以最终会被通信限制。这正是报告里"通信对运行时间的影响"要讨论的内容。

**方案 B：按因子（先转置）**
- 用一次 `MPI_Alltoallv` 把 R 从"按日期分布"转成"按因子分布"：每个 rank 拿到若干个因子的完整 R。
- 之后迭代完全不需要通信，签名天然就在负责它的 rank 上。
- 一次性通信量 ≈ 全部 R 的大小（每个因子约 6.9 MB）。
- 粗略对比：方案 A 每个因子总共传约 4 次 × n × 8 B × 2 ≈ 0.4 MB（4 次迭代各一次 Rᵀu；Allreduce 的系数按 2 计），比方案 B 少，但消息次数多。**哪种更快要实测**，结果和 P、B 都有关。

### 5.2 相似度与准入

- 把档案按行分到各个 rank：每个 rank 算候选和自己那部分档案的相似度，得到局部最大值和位置；再用一次 `MPI_Allreduce`（`MPI_MAXLOC`）得到全局最相似的记录。
- 同一块候选之间的相似度 |Ŝ_c Ŝ_cᵀ| 也并行算好。
- 然后按顺序做准入决定。这一步很快，但是串行的：可以在 rank 0 上做再广播结果，也可以每个 rank 都做一遍（输入相同、结果确定）。报告里要给出它占总时间的比例。
- 准入决定必须和 Python 版**完全一致**，所以要保留"float32 粗算 + 接近阈值时 float64 复核"的机制。

### 5.3 GPU（Vanda 的 A40，48 GB，带宽约 696 GB/s）

- 一块卡可以放约 7000 个 float32 的 R。
- 三个 kernel：
  1. 分段排名：每个线程块负责一个 (因子, 日期) 行，整行 5876 个元素放进 shared memory；
  2. 批量幂迭代 / Lanczos：本质是批量 GEMV，**访存受限**；
  3. 签名相似度：分块共享内存矩阵乘（手写，不用 cuBLAS），**计算受限**。
- 用 roofline 模型分析：实测带宽或 FLOPS 和理论峰值对比。
- MPI + CUDA：每个 GPU 节点有 2 块卡。讲义推荐 `module load nvhpc-hpcx-cuda12/26.1`，支持 CUDA-aware MPI（可以直接对显存指针调用 MPI）。

## 6. 要做的实验

### P0. 正确性

- MPI 签名和串行签名对比：方案 A 只是改了求和顺序，误差应在 ULP 级别；方案 B 应该逐位相同。
- 准入决定和 Python `consider_batch` 对比，要求**完全一致**。

### P1. 串行运行时间随问题规模的变化（评分项）

- 分别改变：因子数 B；抽样间隔（1、2、5、10、20，对应 m）；股票数 n（取子集）；迭代步数 k。
- 画运行时间曲线，坐标轴用对数坐标，并和理论复杂度 O(B·k·m·n) 对比。

### P2. 幂迭代 vs Lanczos（老师的建议）

- 参照答案：Python 里用 numpy 的精确 SVD（只用于验证）。
- 对一代真实的 1 万个因子：
  1. σ₂/σ₁ 的分布：有多少因子的前两个奇异值很接近？
  2. 误差 1 − |cos(签名, 精确签名)| 随 k 的变化，k = 1…10，两种算法各一条曲线；
  3. 达到同样精度（如 1e-6）各需要多少步、多少时间、多少次 Allreduce；
  4. **最关键的一项**：把幂迭代 k = 4 换成 k = 2、8，或者换成 Lanczos，QD 的准入、替换、拒绝决定会变多少个？
  5. 换几个随机种子，决定会变多少？这能说明 4 次迭代是否真的收敛。
- 合成数据：R = U·diag(σ)·Vᵀ + 噪声，人为控制 σ₂/σ₁ ∈ {0.5, 0.9, 0.99}，展示两种算法收敛速度的差别。报告里要写清楚合成数据是怎么生成的。

### P3. MPI 强扩展（≥ 256 核）

- 固定 B（1 万或 3 万个因子），节点数 1、2、4（Vanda 一个 CPU 节点 72 核，4 个节点 = 288 核）。
- 比较方案 A 和方案 B；拆分时间：排名、迭代、Allreduce / Alltoallv、相似度、串行准入。
- 报告加速比、并行效率，并解释通信的影响。

### P4. MPI 弱扩展

- 每个 rank 负责的因子数固定，B 随 P 成比例增加；或者用合成数据增加 n。

### P5. MPI + X

- OpenMP：每个 rank 内用线程并行处理不同因子，或者处理同一因子的不同行。
- CUDA：单卡的 kernel 耗时和 roofline；MPI + CUDA 跨 GPU 节点（每个节点 2 块卡）。

### P6. 档案规模的影响

- 档案大小 A 变化时（从几千到几万），相似度计算和串行准入的耗时变化；分布式档案（MAXLOC）的效果。

验证要写进报告；测试用例挑有代表性的几个即可。

## 7. 你需要的原料

**只有 RankIC 和 fitness 是不够的**：签名要用因子值（准确说是抽样后的 R 矩阵）来算。准入还需要 |RankIC| 和当时的档案状态。

| 原料 | 内容 | 大小 | 用途 |
|---|---|---|---|
| 一代的 R 矩阵 | 1 万个因子的 R，float32，分片存放 | 约 69 GB | P1–P6 的主要输入，不依赖引擎 |
| 开发用小子集 | 例如 500 个因子的 R | 约 3.5 GB | 调试 |
| 这一代的 \|RankIC\| 和因子编号 | 每个因子几个数 | 很小 | 准入需要 |
| 档案快照 | 这一代开始前档案里所有记录的签名、\|RankIC\|、编号 | 几十 MB | 准入和相似度实验 |

| 初始向量 | `pca_init.f8`（长度 n 的 double） | 47 KB | 和 Python 结果一致 |
| （可选）字段数据 + 引擎 | 132 个字段，4.3 GB；从因子值直接算签名，做端到端测试 | 4.3 GB | 和第 ① 部分对接 |
