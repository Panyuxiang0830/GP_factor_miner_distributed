## halo 三种方案（E4，未开始）

| 方案 | 对应 | 怎么做 | 状态 |
|---|---|---|---|
| 一次补齐所需历史 | 策略 A，冗余计算（`H0 ≥ max h`） | 每个 rank 多读 `h` 天的原始字段，本地把整棵树算完，不通信 | ❌ |
| 按需获取子树结果 | 策略 B，子树 halo 交换（`H0 = 0`） | 按 DAG 的 level 逐层算；每层算完后把左邻居需要的尾部 `halo_rows` 行用一次 `MPI_Sendrecv` 发过去 | ❌ |
| 冗余存储 + 按需通信 + 结果复用 | 混合（`0 < H0 < max h`） + 缓存 | 每个 rank 预留 `H0` 天历史；节点的 `h ≤ H0` 就本地补算，`h > H0` 才交换；跨层复用缓存结果 | ❌ |

说明：
- 按日期切块时，一个 rank 缺的历史只会在它的左邻居手里。所以策略 B 不会变成"到处要小数据"：每个 level 只有一次批量 Sendrecv。
- 三种方案共用同一个 `H0` 旋钮。计划先做 B，再用 `H0` 扫出 A 和混合方案。

计划的实验：
- 分别用 p = 1、2、4 和 8 个 rank 跑。
- 对每个 p，`H0` 取 0、10、30、60、89。
- 每次记录这几项：
  - 计算时间；
  - 通信时间；
  - 冗余计算的行数；
  - 显存或内存峰值；
  - 分布式结果与 p=1 是否一致。

### 2026-10-31 E5：串行算子 vs pandas

**做法**
- 数据：真实数据的 120 天 × 300 只股票小样本，132 个字段。
- 用 `python/scripts/export_reference.py values` 让 Python 原版算出 pandas 的标准答案（float64）。
- 用 `tests/test_ops_reference` 比对 C++ 的结果。
- 判定条件：每个元素满足 `|C++ − pandas| ≤ 1e-4·|pandas| + 1e-5·rms(pandas)`，并且 NaN 的位置完全一致。
- 加绝对项 `1e-5·rms`，是因为 pandas 自己有几处在 float32 下计算（pct_change、zscore 的输入），会产生舍入误差。

**用例**
- 0–47：每个算子分别用窗口 1、5、20，外加几个嵌套表达式。
- 50–89：40 个已选因子。

**结果：88 个用例，通过 86 个；约一半在舍入到 float32 后和 pandas 逐位相同。**

| 算子 | 结果 |
|---|---|
| + − × ÷ abs rank lag delta | 误差为 0 |
| mean sum std max min median（窗口 1/5/20） | 误差为 0 |
| ema（窗口 1/5/20） | 误差为 0 |
| pct_change | 误差为 0（改成用 float32 计算之后） |
| correlation、beta（窗口 5/20） | 误差为 0 |
| log | err 1.1e-3（按上面判定公式算出的误差与容差之比，≤ 1 即通过），在 float32 舍入范围内 |
| zscore | err 1.5e-2，max_rel 2.5e-3，原因是 pandas 输入为 float32 |
| 嵌套表达式 / 已选因子 | 38/40 通过 |

**没通过的两个用例**
- 用例 44：`correlation(std(close,10), turnover_rate, 20)`
  - 32 个 NaN 位置不一致；
  - 181 个 inf 与 NaN 互相对不上（约占全部元素的 0.6%）。
- 用例 58：一个已选因子，其中含有 `max(correlation(...))`，1 个 NaN 位置不一致。

**原因**
- 这两个用例都在中间结果 std 上再算 correlation。
- 在 std 几乎不变的窗口里，相关系数的分母接近 0，pandas 自己算出来也是 ±inf 或数值噪声。
- pandas 的中间结果是 float64，我们存成 float32（显存和带宽减半），所以分母是不是恰好为 0 会不一样。

**处理**
- 暂时记为已知差异，不改成 double 存储。
- 等 E6–E8 做完，再看它对日度 RankIC 和 fitness 的影响。影响可以忽略就保留 float32，否则把中间结果改成 double 再比一次。

**调试过程**（报告里可以写成"数值一致性"小节）

| 版本 | 通过数 | 修了什么 |
|---|---|---|
| v1 | 53/88 | 教科书写法：滑动和、滑动方差 |
| v2 | 82/88 | 照 pandas 3.0.3 源码移植：Kahan 求和（加、减分开补偿）、同值序列直接返回原值、Welford 方差 + 数值不稳定时整窗重算、ewm 缺失值时权重衰减 |
| v3 | 86/88 | pct_change 改用 float32；判定条件从纯 rtol 改成 allclose |

教训：
- 舍入上的一点差别，会决定一个窗口算不算"常数"，进而决定 correlation 是 NaN、inf 还是有限值。
- 所以要和原版逐元素对上，必须照抄 pandas 的算法，不能只保证数学上等价。
